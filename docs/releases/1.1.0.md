# rules-corpus 1.1.0

A hardening release over 1.0.0. No schema, digest recipe, canonical JSON form or packed-corpus
format changes; a 1.0.0 corpus verifies and packs the same bytes.

## What changed

- **Limits are validated where set** and bound a packed corpus as a whole
  ([decision 0013](../decisions/0013-limits-are-validated-and-bound-the-whole-archive.md)):
  `CorpusLimits` refuses zero, negative and larger-than-an-array values, and gains
  `MaxPackedEntries` (default 10,000) and `MaxPackedBytes` (default 1 GiB). This is the one
  public .NET change, and it is additive, which is why this is 1.1.0.
- **`pack` is atomic:** the archive is written to a temporary sibling and published only when
  complete, so a failed write leaves nothing and a rerun works.
- **The CLI has one failure boundary**
  ([decision 0014](../decisions/0014-cli-failure-boundary-and-diff-does-not-verify.md)): an
  unexpected exception is `internal error: <type>: <message>`, exit 1, never a stack trace; a
  path the platform cannot represent is a usage error; `verify` refuses a device instead of
  reading it for ever.
- **`diff` says it verified nothing:** help, a note in the human output, and
  `verificationPerformed: false` in `--json` (the one new CLI JSON member).
- Tests for archive and JSON-depth guards that were enforced but untested.

## Compatibility

[compatibility.md](../compatibility.md) applies: exit codes keep their meanings, `--json`
consumers ignore members they do not know, and the .NET baseline is 1.0.0's plus four members on
`CorpusLimits`.

## Deferred

Package distribution (NuGet packages and the `dotnet tool`), the citation-resolution question
(#7), further formats and multi-document corpora are in the [backlog](../backlog.md).
