## What a Part 107 segment is

A `DIV8` element, which in this source is one section: its heading, paragraphs and citation
line, from the start tag to the end tag. The adapter knows nothing about sections; the build
definition names `DIV8` and `N`. The part, subpart, authority and source elements around the
sections belong to no segment.

## Evidence for the tests

`tests/RulesCorpus.Adapters.Xml.Tests` (28 tests, net8.0 and net10.0) over a committed excerpt
of this source: identical results on repeated runs and under reversed parameter order; segment
order and ids; each segment is exactly one element and parses alone; source spans are the
segment's byte range and equal the input's bytes; offsets are bytes across multi-byte
characters, tabs and an astral character; and deterministic refusals for malformed input, a
`DOCTYPE`, a BOM, invalid UTF-8, a CR, another declared encoding, nesting, a missing or
repeated id, a self-closed segment, no match, an unknown or missing parameter and both limits.
`samples/regulatory-xml` runs the same path through the CLI in the gate.

## Is `ICorpusAdapter` demonstrated?

Yes, by two materially different adapters against two different real consumers. `text` (SRD
text, Part 107's earlier plain-text sample) matches lines with regular expressions, records
losses and carries page ranges. `xml` parses a tree language, records none and maps spans
one to one. Both pass the same core validation and the same verify and rebuild path with no
special case, and the contract needed no change. M5 is complete.
